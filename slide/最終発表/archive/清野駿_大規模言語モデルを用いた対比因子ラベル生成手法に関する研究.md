# 背景・問題意識・目的

- 深層学習は高性能だがブラックボックスで、判断根拠を説明できないと信頼・説明責任の面で課題があった
- 従来の説明可能 AI による、特徴に焦点を当てた説明（この画像のこのピクセルは重要度が高い、など）は説明が不安定になりやすく、概念として理解しにくい
- 近年、モデル内部の中間表現から潜在的な概念特徴を発見する研究が進展  
  ただし、その概念が何を意味するか（画像に尻尾のようなものが含まれている、など）の命名は人手に依存しがち
- そのため、概念に対して自動で命名する手法が研究されてきた

---

# 本研究の位置づけ

- 既存の自動命名手法は、モデル内部の中間表現の直接アクセスが前提で、専用のモデル構築が必要という点で課題
- モデルの入出力という外部データのみで行うラベル生成手法も存在するが、大規模なデータセットによる実務的な評価は行われていない
- LLM を活用することで外部的に差分説明を行う研究も存在するが、説明可能 AI の文脈では活用されていない
- **目的**：正解アスペクトによって分割した（人手で正解が付与されている）実務的なデータセットを用いて、LLM がどれだけ概念に対して妥当なラベル生成をできるか検証すること

---

# 問題設定：対比因子ラベル生成タスク

入力：2 つのテキスト集合 $A,B$

$$
\texttt{textContrastiveLabeling}(A,B) \mapsto L
$$

- $A$：外部ラベル（アスペクト等）を含むテキスト集合
- $B$：外部ラベル（アスペクト等）を含まないテキスト集合
- **対比因子ラベル $L$**：$A$ と $B$ を分ける主要な要因（対比因子）を表す短いフレーズ

例：A に価格・コスパ不満が多い → `high prices and poor value for money`

---

# 手法：LLM による対比因子ラベル生成

- グループ $A/B$ の代表テキストを入力として提示し、両者を分ける対比因子ラベル $L$ を生成させる
- 例題を挿入する場合：冒頭に「グループ A/B → 対比因子ラベル」の入出力例を置き、出力の形式・語彙を誘導する

<style scoped>
pre { font-size: 0.62em; }
</style>

```
以下の2つのデータグループを比較して、グループAに特徴的で
グループBには見られない主要な対比因子を特定してください。

（必要ならここに【例題】を挿入）

【グループA】
- ...
...

【グループB】
- ...

英語で5–10語程度の対比因子ラベルとして、簡潔に回答してください。
```

---

# 実験

- LLM が生成する対比因子ラベルの品質を、実務的な環境で定量評価する
- そのために、アスペクトが付与済みのデータセット（商品レビュー等）を用いる
- 各アスペクト（価格、サービス等）について，アスペクトを含む／含まないテキスト群を $A/B$ の 2 グループに分割。LLM は $A/B$ を入力として、$A$ に特徴的で $B$ に見られない要素を対比因子ラベル $L$ として生成する
- 生成した対比因子ラベルと正解ラベル（アスペクト名）の一致度を，意味的一致（SBERT 類似度）と語彙的一致（BLEU）および LLM による 5 段階の評価で測定する

---

# 実験：使用データセット

本実験では以下の４つのデータセットを用いる

- **SemEval-2014 ABSA**：7,694 レコードの商品レビューデータセット。Food/Service/Battery/Screen の 4 アスペクトを使用。
- **GoEmotions**：54,263 レコードの感情分類データセット。驚き、喜びなどの 28 アスペクトで構成される。
- **Steam**：22,954 レコードのゲームレビューデータセット。Gameplay/Visual/Story/Audio の 4 アスペクトを使用。
- **COCO Retrieved Concepts**：画像キャプションデータセット。コサイン類似度によるクラスタリングで画像ベクトルをいくつかに分類後、各クラスタの画像のキャプションを用いてグループ A/B を作成した。正解ラベルなし。

---

# 実験：設計（6 カテゴリ）

- **共通設定**：生成モデルは GPT-4o-mini、AB グループそれぞれ 100 テキストで比較

**1. データセット別比較**：SemEval-2014、GoEmotions、Steam で基本性能を評価
**2. Few-shot 実験**：0/1/3-shot で例示数の影響を検証
**3. グループサイズ比較**：group_size（50–300）で入力テキスト数の影響を分析
**4. モデル比較**：GPT-4o-mini vs GPT-5.1 でモデル差を検証
**5. アスペクト説明文比較**：評価時にアスペクト名の代わりに説明文を使用（例："gameplay" → "this review contains gameplay" vs LLM 生成ラベル）
**6. COCO 実験**：正解ラベルなしデータセットで成功/失敗例を分析

---

# 実験 1：データセット別比較

| データセット(アスペクト数) | 平均単語数 | 平均 SBERT 類似度 | 平均 BLEU | 平均 LLM 評価 |
| -------------------------- | ---------: | ----------------: | --------: | ------------: |
| SemEval-2014（4）          |       19.9 |        **0.7481** |    0.0151 |    **0.5500** |
| GoEmotions（28）           |       12.8 |        **0.7055** |    0.0049 |    **0.4714** |
| Steam（4）                 |  **244.7** |            0.5328 |    0.0000 |        0.2500 |
| 全体（36 条件）            |       17.8 |            0.6910 |    0.0055 |        0.4556 |

- **SemEval/GoEmotions でスコア高**：特に SemEval では 0.74 と一定の意味的相関が見られた。長文の Steam では性能が低下した。
- **評価指標の妥当性と相関**： 説明的な生成ラベルに対しては語彙一致（BLEU）は機能しないが、意味類似度（SBERT）と LLM 評価には強い正の相関（$\rho=0.73$）を確認でき、提案手法の妥当性が示された。

---

# 実験 2：Few-shot（Steam 4 アスペクト）

| 例題数 | 平均 SBERT 類似度 | 平均 LLM 評価 |
| ------ | ----------------: | ------------: |
| 0-shot |            0.5526 |        0.3000 |
| 1-shot |        **0.6530** |        0.3500 |
| 3-shot |            0.5754 |    **0.4000** |

- **1,3-shot でスコア最大**：1-shot で BERT が最大化、3-shot では LLM 評価が最大化するなど、例示数増加が全指標を一律に改善させるわけではない。
- shot 数間で有意差はなく（$p=0.47$）、手法の工夫（Few-shot）による変動よりも、アスペクト自体の抽出難易度、つまりデータセットの性質が結果に影響すると考えられる。

---

# 実験 3：グループサイズ比較（Steam 4 アスペクト）

| group_size | SBERT 類似度 | LLM（平均） |
| ---------: | -----------: | ----------: |
|         50 |       0.5455 |      0.3000 |
|        100 |       0.5436 |      0.3500 |
|        150 |       0.5321 |      0.2500 |
|        200 |       0.5396 |      0.3000 |
|        300 |       0.5375 |      0.2000 |

- サンプル数を増やしても性能は向上しなかった。
- サンプル数の増加は差分に関係のない周辺話題（ノイズ）の混入を招く。その結果、抽出すべき対比の焦点がぼやけたと考えられる。

---

# 実験 4：モデル比較（Steam 4 アスペクト）

| モデル  | 平均 SBERT 類似度 | 平均 LLM 評価 |
| ------- | ----------------: | ------------: |
| 4o-mini |            0.5453 |        0.3000 |
| 5.1     |            0.5375 |        0.2500 |

- 最新の大型モデル（GPT-5.1）が軽量モデル（4o-mini）を一貫して上回る傾向は見られず、平均性能に統計的な有意差（$p=0.875$）は認められなかった。

# 実験 6：COCO Retrieved Concepts（概要）

- COCO train2017 を CLIP で類似度分割し、各コンセプトで A=Top-100 / B=Bottom-100 のキャプション差分からラベル生成
- 正解ラベルがないため、生成ラベルは代表画像との整合で成功/失敗要因を定性的に確認

# 実験 6：総括（COCO）

- 成功条件：集合が単一概念としてまとまる／語彙手がかりが強い
- 失敗条件：概念混在・周辺話題の混入で差分が弱い
- 示唆：正解ラベルがなく人間にとって意味づけしづらい類似度構造でも、差分から妥当な概念語を付与できた例があり、未知概念ラベリングに可能性

---

# 結論

- **主結果**：SBERT 類似度は平均 0.69 程度で、最大 0.74 と一定の効果が見られた
- **示唆**：短文・単一概念にまとまる条件で安定し、長文/ノイズ混入で性能が落ちやすい
- **正解なしデータ**：成功例があり、未知概念（中間表現）へのラベリングに可能性
